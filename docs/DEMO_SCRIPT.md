# 1차 시연 영상 대본: 폭우 드릴 (60~90초 화면 녹화)

목표: 심사위원이 85초 안에, 진짜 조작을 차 값(Vehicle SDK)이 판정한다는 것을 눈으로 확인하게 한다.

형식: 목업, 프로토타입, 화면 녹화 모두 인정된다. 내레이션 없이 자막만으로도 이해되게 만든다.

## 1. 화면 배치

```
┌──────────────────────────────┬───────────────────┐
│  Pleos Connect 에뮬레이터     │  Virtual Console  │
│  (차 길들이기 앱, 가로)        │  Wipers / Gear /  │
│        약 70%                 │  Defroster /      │
│                              │  Exterior Lights  │
├──────────────────────────────┴───────────────────┤
│  자막 띠 (하단, 2줄 이하)                           │
└──────────────────────────────────────────────────┘
```

- 녹화 영역은 두 창만 잡는다. 전체 화면은 녹화하지 않는다. macOS에서 `⌘⇧5`를 누르고 선택 부분 기록을 고른다.
- 앱은 Pleos 홈 화면의 오른쪽 창(약 1707x1210 px)에 뜬다.
- 출력은 1920×1080, 30fps. 마우스 클릭 표시를 켜 두면 콘솔 조작이 잘 보인다.
- 콘솔 카드는 쓰는 것만 보이게 스크롤해서 정리한다. Gear Selection, Exterior Lights Mode, Wipers, Defroster만 쓰고, Steering Wheel Heat는 이번 영상에서 쓰지 않는다.

## 2. 녹화 전 준비 (리허설 1회 필수)

1. release APK(`apk/` 안의 제출 파일)를 사용자 Pleos 에뮬레이터에 설치한다. 제출본과 같은 APK로 찍는다.
2. 앱 데이터를 지운 뒤 실제 신호로 폭우 드릴을 한 번 끝까지 리허설한다. 이 기록이 완료 화면의 지난 기록이 된다. 시뮬레이션으로 만든 기록이 남아 있으면 지우고 다시 리허설한다. 가짜 기록과 비교하면 안 된다.
3. 콘솔 조작이 앱에 어떤 값으로 읽히는지는 Pleos Connect v2.1.0에서 이미 확인했다. 리허설에서는 아래대로 나오는지만 본다.
   - Wipers Low는 `CONTINUOUS_LEVEL_1`, High는 `CONTINUOUS_LEVEL_3`으로 읽히고, 둘 다 와이퍼 단계를 통과한다.
   - Wipers Auto는 `AUTO`로 읽히고 다른 칸 안내("AUTO는 센서에 맡겨요")가 뜬다. 콘솔에는 MIST가 없고 폭우에는 High도 정답이라서, 다른 칸 장면에는 Auto만 쓴다.
   - Exterior Lights Mode는 Low beam만 전조등 스위치 `ON`으로 읽혀 전조등 단계를 통과한다. Auto, Tail lamp, Off는 모두 `OFF`로 읽힌다. 그래서 장면 3은 A안(Low beam)으로 찍는다.
   - Defroster의 Front는 앞유리, Rear는 뒷유리 구역으로 읽힌다.
   - Gear P는 `GEAR_PARK`로 읽힌다. Gear를 D로 바꾸면 Pleos가 앱 화면을 가리고 "주행 중에는 사용할 수 없습니다"를 띄운다.
   - "값이 아직 그대로예요" 버튼은 전조등, 김서림, 열선 단계에만 나온다. 와이퍼 단계는 레버 값으로만 통과한다.
   - 홈 출처 칩이 시뮬레이션이 아니라 `차 신호`인지 본다. 시뮬레이션으로 넘어가면 녹화를 멈추고 권한 같은 원인부터 해결한다(`docs/compliance/REVIEW.md` 2장).
4. 시작 상태: 콘솔 Gear P, Wipers Off, Defroster Off, Lights Off 또는 Auto(둘 다 `OFF`로 읽힌다). 앱은 홈 화면.

- 시간 초과 화면은 이번 영상에서 쓰지 않는다. 필요하면 2차 PT에서 보여 준다.

## 4. 시뮬레이션으로 찍는 경우 (B 계획)

사용자 Pleos 에뮬레이터에서 녹화하기 어려우면 미리보기 에뮬레이터의 시뮬레이션 모드로 찍을 수 있다. 그때는 이렇게 한다.

- 제목 카드 고지를 `시뮬레이션 모드 녹화 · 앱 안 시뮬레이터로 신호를 바꿉니다 · 실제 차 신호가 아닙니다`로 바꾼다.
- 출처 칩 `시뮬레이션`, 화면 위쪽 시뮬레이션 배지, 시뮬레이터 패널의 `시뮬레이션 중이에요. 실제 차 신호가 아니에요` 문구가 모든 장면에 보여야 한다. 잘라 내지 않는다.
- 자막의 차가 판정한다는 표현은 앱이 판정한다(시뮬레이션 신호)로 바꾼다. Virtual Console은 함께 띄우지 않는다. 콘솔이 신호를 보내는 것처럼 오해할 수 있다.
- 일부 장면만 시뮬레이션이면 그 장면 자막 끝에 `(시뮬레이션)`을 붙인다.

## 5. 자막 규칙

- 화면 아래에 고정하고 2줄 이하, 줄당 20자 안팎으로 쓴다. 문장은 짧게, 말은 쉽게. 영어 enum 이름은 화면에 보이는 값 그대로만 쓴다(`AUTO`).
- 낱말 중간에서 줄을 바꾸지 않는다. 내 차, 한 단계, 기어 D 같은 묶음은 한 줄에 둔다.
- 앱에 없는 기능은 말하지 않는다. 음성(TTS)이 구현되지 않았으면 소리로 알려 준다고 쓰지 않는다. 현대차가 올린 퀘스트를 보여 줄 때는 화면 라벨 `제조사 안내 · 예시`가 보여야 한다.
- 숫자(통과 시간, 기록 차이)는 화면에 나온 실제 값만 쓴다. 자막에 숫자를 미리 적어 두지 않는다.

## 6. 녹화 개인정보 점검표 (녹화 직전)

- [ ] macOS 집중 모드(방해 금지)를 켰다. 메신저, 메일, 캘린더 알림이 뜨지 않는다.
- [ ] 녹화 영역이 두 창만 덮는다. 메뉴 막대, Dock, 바탕화면 파일명, 다른 창이 보이지 않는다.
- [ ] Pleos 에뮬레이터 상태 표시줄, 설정 화면, 프로필에 계정 이메일이나 이름이 보이지 않는다. 보이면 그 화면을 거치지 않거나 잘라 낸다.
- [ ] Virtual Console과 에뮬레이터 창 제목에 사용자 폴더 경로(`/Users/...`)가 보이지 않는다.
- [ ] 터미널, Android Studio, 브라우저 탭(특히 GitHub 계정, 메일)이 화면에 없다.
- [ ] 마이크를 껐다. 주변 소리나 목소리가 녹음되지 않는다. 내레이션을 넣는다면 따로 녹음한다.
- [ ] 완료 화면과 로그에 개인정보가 없다. 앱은 이름을 받지 않으니 확인만 하면 된다.
- [ ] 내보낸 영상 파일의 메타데이터(제목, 작성자)에 실명이 없다. 파일명 예: `<팀명>_차길들이기_시연.mp4`
- [ ] 영상 파일은 용량과 개인정보 때문에 저장소에 커밋하지 않는다. 제출 페이지 안내에 따라 업로드한다.
- [ ] 다 찍은 뒤 처음부터 끝까지 한 번 보며 위 항목을 다시 확인했다.
